# 006 — مخرجات Claude Design بتطلع بعيوب ثابتة

**الحالة:** ♻️ بتتكرر — اتصلحت بالإيد أكتر من مرة، وبترجع مع كل توليد جديد
**آخر مرة:** 2026-08-31 (شاشات 15 → 21)

## إيه اللي شفناه

كل ما نولّد شاشة جديدة على Claude Design، بتيجي بعيب أو أكتر من اللستة دي:

| العيب | التفصيل |
|---|---|
| **ملف canvas واحد** | بدل ملف `.dc.html` منفصل لكل artboard، بيرمي كله في ملف واحد |
| **`<script data-dc-script>` ناقص** | البلوك اللي في آخر الملف بيسقط خالص |
| **`<!DOCTYPE html>` بحروف كبيرة** | باقي الملفات بتستخدم `<!doctype html>` صغيرة |
| **الخط العربي مش متستورد** | `IBM Plex Sans Arabic` مش متعمله import |
| **classes مستخدمة من غير تعريف** | ⚠️ **أكتر عيب متكرر** — خصوصًا `fv` و`fvd` (focus-visible) و`sk` (skeleton) |
| **خصائص CSS فيزيائية** | `margin-left` بدل `margin-inline-start` — بيكسر الـ RTL |
| **`#000000` كخلفية داكنة** | المفروض `#121317` |
| **الأولوية والحالة مدموجين** | المفروض badge منفصلين |
| **اسم فولدر غلط** | حصل فعلًا: فولدر اسمه `21.WisalOrgSettings-Departments` وجواه ملف Branches |

## ليه حصل

سببين مختلفين:

1. **برومبت فيه أكتر من شاشة.** ده موثّق كسبب مباشر لمشكلة الـ canvas الواحد.
   القاعدة اللي اتحطت بعدها: **كل ملف برومبت = شاشة واحدة = جلسة Claude Design جديدة وفاضية.**
2. **نموذج توليدي، مش قالب.** المخرج بيتولّد من الأول كل مرة، فمفيش ضمان إن قاعدة اتنفذت
   المرة اللي فاتت هتتنفذ تاني. حتى لما البرومبت بيقول القاعدة صراحة.

## الحل

مفيش حل نهائي — دي **قائمة فحص لازم تتشغّل على كل مخرج جديد**، موجودة في
`docs/requirements/required-for-System-ERP/ستوري-تيلينج/design-prompts/00-README.md`:

1. ملف `.dc.html` منفصل لكل artboard، مسمّى زي اللابل بالظبط
2. آخر الملف فيه `<script data-dc-script>`
3. **كل `class="..."` في الـ markup معرّفة في `<style>`**
4. مفيش `#000000` كخلفية داكنة — لازم `#121317`
5. الأولوية والحالة badge منفصلين
6. خصائص CSS منطقية (`margin-inline-start`) مش فيزيائية
7. الهيدر كامل — [شوف مشكلة 007](007-app-shell-header.md)
8. **افتح الفولدر واتأكد إن الاسم مطابق للمحتوى جواه**
