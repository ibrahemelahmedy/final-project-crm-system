# 004 — الفرونت والـ API على عنوانين مختلفين

**الحالة:** ✅ متحلّة
**التاريخ:** 2026-08-30
**الكوميت:** `32c04ee`

## إيه اللي شفناه

الفرونت مرفوع على مشروع Vercel، والـ API على مشروع تاني (`wisal-crm-api.vercel.app`).
يعني المتصفح بيطلب من **origin مختلف** — وده بيفتح باب CORS وكل وجعه (preflight، هيدرز،
كوكيز، وعنوان الـ backend مكشوف للعميل).

## ليه حصل

قرار معماري مقصود: الفرونت (React) والباك (Laravel) متنشرين كمشروعين منفصلين على Vercel.
ده كويس للنشر، بس بيخلّي المتصفح شايفهم كموقعين مختلفين.

## الحل

بدل ما نتعامل مع CORS، خلّينا **Vercel نفسه** يعمل proxy على مستوى السيرفر.
سطر واحد في `web/vercel.json`:

```json
{
  "rewrites": [
    { "source": "/api/(.*)", "destination": "https://wisal-crm-api.vercel.app/api/$1" },
    { "source": "/(.*)", "destination": "/index.html" }
  ]
}
```

النتيجة:

- المتصفح بيطلب `/api/tickets` — يعني **نفس الـ origin**، مفيش CORS خالص.
- Vercel بيحوّل الطلب للـ Laravel من ورا الكواليس.
- عنوان الـ backend **مش بيظهر في المتصفح أصلًا**.

⚠️ **الترتيب مهم:** قاعدة `/api/(.*)` لازم تيجي **قبل** قاعدة الـ SPA `/(.*)`.
لو اتعكسوا، كل طلبات الـ API هترجع صفحة `index.html`.

## درس مستفاد

قبل ما تحارب CORS بالهيدرز، اسأل: أقدر أخلّي الطلب same-origin من الأساس؟
الـ rewrite على مستوى منصة النشر أبسط وأأمن من ضبط CORS يدوي.
